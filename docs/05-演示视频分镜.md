> 唯一拍摄脚本。口播可直接照念，不要临场改词。成片 **7:05**（硬上限 8:00，预留 55 s）。

### 分段状态与复位（保证每段数字可复现）

视频是分段录的，**每段开录前把数据复位到该段的初始状态**，否则上一步的入库/对账会改变下一步的数字（例如 S2 入库 8 条后再对账，会变成「8 条全不见」）。

| 段 | 开录前状态 | 复位 / 准备命令（`apps/server` 下） |
|---|---|---|
| S1 | seed（在库 8 条、30 天历史） | `python scripts/seed_demo.py --reset` |
| S2 | 同 S1 | 同上；录完可不管，S3 会复位 |
| S3 | 同 S1 | 同上（**必须在 S2 之后重新复位**，否则对账结果是 8 条不见） |
| S4 | 同 S1，清空偏好，且盖过核验时间（避免顶部「超过 3 天未核验」提示） | `python scripts/seed_demo.py --reset` → 清偏好（见下）→ 用 API 盖核验时间（见下，界面里「全部保留」时按钮是禁用的） |
| S5 | 接 S4 同一状态（同一份 plan） | 不复位，直接在 S4 生成的计划上改 |
| S6 | 同 S1（30 天历史 1650 g 丢弃 / 8470 g 吃掉） | `python scripts/seed_demo.py --reset` |
| S7 | 同 S1（推荐现场生成，不复位） | 直接进「今日吃啥」生成一次推荐；「已降级」片段用 mock 另录一条 |

> S3 的「丢弃 4 条」写在它自己的状态里，S6 是复位后的另一份账，两者不叠加；口播也没有把二者串成一句，不会出现画面矛盾。

> **清偏好**（`seed_demo --reset` 不清 `preferences`；不清理会让计划少用一样，coverage 变成 `5/3/1`、采购 11 项，与口播的 `5/2/2`、6 项不符）：

>

## S2 · 0:30–1:40 拍冰箱识别 + 人工校对（70 s）

| 项 | 内容 |
|---|---|
| 画面 | ①点左侧「拍照入库」→ 默认在「拍冰箱」②点上传区选 `samples/fridge-pd/fridge-pd-1.jpg` ③「正在识别」卡片（真实 provider 约 5 s，mock 立即）④结果卡：「识别到 8 条，需要确认 2 条，已选 8 条」⑤镜头停在酸奶那行：`0.55` 黄标 + 「置信度偏低，请人工确认」⑥镜头停 1.5 s 在秋葵那行：「未匹配食材库（不计入碳账）」⑦把番茄数量 3 改成 2 ⑧点「确认入库 8 条」→ 成功卡「已入库 8 条」+「生成 3 天饮食计划」按钮 |
| 操作要点 | 第 ⑤⑥ 步各停 1.5 s，让评委看清黄标与「不计碳账」；改数量时只改一个字段，别连点；mock 录制时结果卡会多一条「当前为 mock 回放数据」，照实留着 |
| 评分点 | 多模态 5（拍照理解）/ 安全 4（识别不入库、置信度、库外过滤）/ 交互 7（校对表单不是聊天框） |

**口播（222 字）**：

> 第一个动作是拍。选一张自己拍的冰箱内景，上传。后端把图转成 base64 交给视觉模型，按我们写死的 JSON 结构返回名称、数量、单位和置信度。这次回来 8 条：1 条置信度 0.55，标黄；1 条不在食材库，标成库外食材，不计碳账。识别结果不会直接进库存，它先变成一张能改的表：名称、数量、到期日都能动，取消勾选就不提交；底部还能手动补一行。上传上限 8 MB，前后端都按常量算，不写死在页面里。我把数量改成 2，点「确认入库 8 条」才真正写库，到期日按食材表补齐。

## S3 · 1:40–2:43 库存对账（63 s）

| 项 | 内容 |
|---|---|
| 画面 | ①「拍照入库」页切到「对账」标签 ②上传 `samples/fridge-2.jpg` ③「正在核对」→「② 逐类核对」，三组折叠：**不见了 4 / 新增 3 / 看不清 1**（「变少了」为 0 时不显示）④展开「不见了」，镜头停在提示「默认保留，删除必须由你确认」⑤把 4 项依次点「扔掉了」，原因选「坏了」⑥展开「看不清」，读一句「识别置信度低（0.55），无法确认是否还在」⑦点「应用对账（4 项）」→「对账已应用」卡：丢弃 4 / 吃掉 0 / 更新数量 0 / 新增 0 |
| 操作要点 | 强调「默认为保留」；应用前停 1 s 给评委看汇总条；成功后回首页，顶部「超过 3 天未核验」提示消失 |
| 评分点 | 创新·方案 8（AI 不擅自改数据）/ 安全 4（默认 keep、suspect 不判 missing、幂等 apply） |

**口播（203 字）**：

> 隔几天冰箱会变。切到「对账」，再拍一张。系统只拿在库的库存和这张照片逐项比：这次 4 项不见了，3 项是新增，1 项因为看不清进了待确认。注意默认动作全是「保留」，删除必须我亲手点；不见了的那几项选「扔掉了」，还要选原因。对账这一步是只读的，不改数据；真落库要再点一次应用，这就是它和「AI 全自动」的区别。点「应用对账」，四条丢弃写进浪费账，同时给整批库存盖一次核验时间，首页那条「超过 3 天未核验」的提示才会消失。

## S4 · 2:43–3:53 3 天计划（70 s）

| 项 | 内容 |

| 画面 | ①点「饮食计划」②顶部参数卡：计划天数「3 天」、单餐时长「30 分钟」③点「生成计划」④生成中先出现步骤流（understand→plan→allocate→compose→verify 逐条点亮），再出现三列日卡（6 餐）⑤镜头扫顶部统计：用掉食材 5 · 救下临期 2 · 临期没用上 2 ⑥展开一条提示「「菠菜」已过期 1 天，先处理掉（不会进计划）」⑦点某餐引用角标 1 → 弹窗显示菜谱原文 ⑧滚到「采购清单」（6 项），读「缺料已按食材合并，不会重复列同一样东西」⑨回到顶部 |
| 操作要点 | 过期提示必须拍到；引用弹窗停 2 s；采购清单只滚一半，别逐条念；mock 录制时 compose 会显示「已降级」，属诚实降级，不要剪 |
| 评分点 | Agent 8（五步 + verify）/ 实用 10（真实库存、可核对 coverage）/ RAG 6（引用回链） |

**口播（231 字）**：

> 接着排饭。「饮食计划」页默认 3 天、单餐 30 分钟，点「生成计划」。参数也能改成 2 天或 5 天，单餐压到 20 分钟，这些约束会进 Agent 的第一步。它先剔除过期食材——这把菠菜过期 1 天，只出现在提示里，不进计划。然后按到期顺序做贪心分配：3 天 6 餐，用掉 5 样，其中 2 样是 3 天内到期的，还有 2 样临期没排上，页面直接告诉我。每餐用量从库存里逐餐扣，同一道菜重复出现会减分，不够的自动转成缺料。缺料合并成一张采购清单，同一样不会重复列。每餐都挂真实菜谱 id 和引用，点角标能看原文。

## 3. 数字替换与降级预案
