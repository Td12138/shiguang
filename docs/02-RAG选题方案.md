## 1. 三个选题（按实用性排序）

### 选题 A「查证」· 可信知识库问答

**一句话**：给企业/社团内部资料建库，回答每个问题都附带证据链——哪一段、第几页、哪份文件、什么时候生效，并且**主动告诉你哪几段在互相打架**。

| 项 | 内容 |
|---|---|
| 真实痛点 | 内部 Wiki/客服话术/规章制度版本混乱，同一问题三份文档三个答案；误传或恶意条目没人发现 |
| 核心功能 | ① 多格式入库（PDF/Word/图片 OCR/网页），每块带来源与页码<br>② 混合检索（向量 + 关键词）<br>③ 多文档各自作答 → 投票聚合（RobustRAG）<br>④ **冲突面板**：同问题下互相矛盾的段落并排展示<br>⑤ 引用角标 → 点开定位原文<br>⑥ 「投毒演练」开关：注入 3 条毒文档，现场对比防护前后 |
| 复用 | 本人存量 RAG 项目的检索与多文档投票思路、cam-ocr、yizhi-chengke 的质检回环 |
| 评分覆盖 | RAG 6/6、Agent 8/8、安全 4/4、工具 4/4，多模态靠拍照入库（3/5） |
| 72 小时可行 | 可行。难的是引用定位 UI，不是算法 |
| 风险 | 「冲突检测」要做成可解释（并列两段原文 + 相似度/时间），不能只给个红点 |

### 选题 B「政策通」· 学生/个体户政策匹配

**一句话**：说一句「我是大三在读、家里个体户、想申请创业补贴」，直接给出你能申报的项目、逐条核对条件、标注截止日期，每条结论挂原文条款。

| 项 | 内容 |
|---|---|
| 真实痛点 | 政策文件长、跨部门、附件藏条件、旧版本还在传 |
| 核心功能 | 情况录入 → 条件逐条判定（满足/不满足/需补材料）→ 原文引用 + 生效日期 → 过期条款自动标灰 |
| 复用 | RAG 检索 + 版本冲突检测（同一政策多版本是天然语料） |
| 评分覆盖 | RAG 6、Agent 6、安全 4，多模态弱 |
| 72 小时可行 | 中。代码不难，**难在语料**：要 20–50 份真实公开政策，还得核对时效 |
| 风险 | 政策时效性一旦被评委抓到过期条款，可信度全崩；需明确免责 |

### 选题 C「说明书管家」· 家电维修与保修问答（绿色生活包装）

**一句话**：拍家电铭牌或说明书页 → 入库 → 问「E3 故障码什么意思」「保修几年」「耗电多少」→ 带页码引用回答；顺带算「修 vs 换」的碳账。

| 项 | 内容 |
|---|---|
| 真实痛点 | 说明书随手丢、故障码搜不到、保修期记不住，结果小故障直接换新 → 电子垃圾 |
| 核心功能 | 拍照/上传入库（OCR）→ 问答带页码 → 故障码索引 → 保修倒计时 → 「修 vs 换」碳排对比 |
| 复用 | cam-ocr + RAG 检索 + 碳因子表 |
| 评分覆盖 | 多模态 5/5（拍照是主入口）、RAG 6、安全 3、Agent 5 |
| 72 小时可行 | 高。数据自备（找 5–10 份真实说明书 PDF 即可演示） |
| 风险 | 品类窄，创新性中等；但落地感和演示稳定性最好 |

## 3. 共同的技术底线（三个选题都要有）

| 评分项 | 最低要求 |
|---|---|
| Agent | 查询改写 → 多路检索 → 投票 → 引用自检 → 不过则重写，trace 面板可见 |
| RAG | 向量 + BM25 混合；引用必须能点回原文位置 |
| 安全 | 低置信度显式标注；无依据时回答「资料里没有」而不是编 |
| 工具 | Function Calling 注册表：检索/OCR/日期计算/冲突检测 |
| 多模态 | 至少一条真实链路：图片 → 文字入库；语音提问用浏览器 Web Speech API（零成本） |
