# 09 部署方案（cloudserver200m）

> 事实源：`scripts/deploy.ps1`（发布/回滚）、`deploy/install.sh`（首次安装）、`deploy/harden-existing.sh`（存量修复）、`deploy/shiguang.service`（unit）。
> 本文只描述脚本实际行为；脚本改了这里必须同步改。

## 1. 形态

| 项 | 值 |
|---|---|
| 主机 | `cloudserver200m`：公网 `47.100.224.209`，Tailscale `100.77.67.31` |
| 规格 | Ubuntu / 1.6 GB 内存 / 40 GB 盘 / Python 3.12.3 / systemd 255 |
| 访问方式 | `http://47.100.224.209:8720`（阿里云安全组放行 TCP 8720） |
| 进程 | 单 worker uvicorn，systemd 托管，FastAPI 直接托管 `apps/web/dist`（不装 nginx，省内存） |
| 运行用户 | `shiguang`（系统用户，`nologin`、无 home）；**不用 root 跑 Web** |
| 代码归属 | `releases/*` 归 `root:root`，目录 755、文件 644（非 root 不可改） |
| 数据 | `/opt/shiguang/shared/app.db`（`shiguang:shiguang` 640），用 `sqlite3 .backup` 热备份（见 §10） |
| 模型 | 默认 `mock`（首次安装自动生成）；切 `zhipu` 时只改服务器 `shared/.env`，key 不进仓库 |

## 2. 目录与权限

```
/opt/shiguang/                      755 root:root
  releases/20261117-210000/         755 root:root     # 每次发布一个新目录，代码 644
    apps/server/app/...
    apps/server/.env -> /opt/shiguang/shared/.env       # 软链，配置只有一份
    apps/web/dist/...
  current -> releases/20261117-210000                 # 回滚只改这一条链接
  shared/                           750 shiguang:shiguang
    .env                            640 root:shiguang # 服务用户组只读，其他人不可读
    app.db                          640 shiguang:shiguang
    upload/                         750 shiguang:shiguang
  venv/                             755 root:root     # 依赖只读
  last-deploy.txt                   644 root:root     # 最近一次成功发布 + 上一版路径
```

`.env` 与 `app.db` **只存在于 `shared/`**：切软链不会丢配置和数据库；release 内不放任何可写文件。

## 3. 首次部署

前置：本机有 `~/.ssh/TDserver_200M.pem`；阿里云安全组已放行 TCP 8720。

```powershell
# 一条命令：构建 → 打包 → 上传 → 解包定权 → 建用户/venv/生成 .env → 切链 → 启动 → 健康门
pwsh -File scripts/deploy.ps1 -FirstRun
```

脚本内部顺序（不需要手工补步骤）：

| 阶段 | 动作 |
|---|---|
| 预检 | `ssh -o BatchMode=yes -o ConnectTimeout=10`；检查远端 root、`curl/systemctl/tar`，记录上一 release（首次运行缺 venv/用户由 `-FirstRun` 补建） |
| 构建 | `apps/web` 下 `pnpm install --frozen-lockfile` → `pnpm build`；**任一步退出码非 0 立即失败** |
| 必需文件 | `apps/web/dist/index.html`、`apps/server/requirements.txt`、`LICENSE` 缺一即停 |
| 打包 | `apps/server/{app,scripts,mcp,requirements.txt}` + `apps/web/dist` + `README.md` + `LICENSE` + `THIRD-PARTY-NOTICES.md`；剔除 `__pycache__`/`*.pyc` |
| 解包 | 远端 `umask 022`；目录 755、文件 644、`chown -R root:root`；`shared` 归 `shiguang:shiguang` |
| 安装 | 上传并执行 `deploy/install.sh`：建 `shiguang` 用户、venv、随机口令 `.env`、装 unit |
| 启动 | `ln -sfn <release> current` → `systemctl enable --now` → `restart` |
| 健康门 | `curl -fsS http://127.0.0.1:8720/api/health` 必须含 `"ok":true`，否则切回上一 release 并 `exit 1` |

> **不要手工建空 `.env`**：空文件意味着 `SHIGUANG_BASIC_AUTH` 未设置 → Basic 认证关闭 → 公网裸奔。
> `.env` 由 `install.sh` 随机生成并设为 `640 root:shiguang`；口令**不打印**到 stdout，从文件取值后登记到 `user/凭证/台账.md`。
> `install.sh` 幂等可重跑；缺 `python3-venv` 时会尝试 `apt-get install -y python3-venv`（失败即停并给出手工命令）。
> 启动前会校验 `SHIGUANG_BASIC_AUTH` 非空：为空直接 `exit 1`，**不会**把无认证服务拉起来。

## 4. 服务端 `.env` 关键项

文件：`/opt/shiguang/shared/.env`（640 `root:shiguang`）。改完执行 `systemctl restart shiguang`。

| 键 | 取值 | 说明 |
|---|---|---|
| `SHIGUANG_LLM_PROVIDER` | `mock` | 要真模型改 `zhipu` 并填 key |
| `SHIGUANG_LLM_API_KEY` | 空 | 只存服务器，永不入库/不进日志 |
| `SHIGUANG_DB_PATH` | `/opt/shiguang/shared/app.db` | 固定绝对路径，切 cwd 不换库 |
| `SHIGUANG_UPLOAD_DIR` | `/opt/shiguang/shared/upload` | 同上 |
| `SHIGUANG_WEB_DIST` | `/opt/shiguang/current/apps/web/dist` | 走软链，回滚后静态资源同步 |
| `SHIGUANG_BASIC_AUTH` | `demo:<口令>` | **必须非空**；空 = 不启用认证 |
| `SHIGUANG_RATE_LIMIT_PER_MIN` | `120` | 限流额度，见 §6；`0` = 关闭 |
| `SHIGUANG_SSL_VERIFY` | `os` | 系统信任库 |

存量 `.env` 不被 `install.sh` 覆盖，只修正归属/权限；限流低于 120 时脚本会打印待办。

## 5. systemd 单元

`deploy/shiguang.service`（唯一副本，装到 `/etc/systemd/system/`）：

```ini
[Unit]
Description=Shiguang demo (Chuanzhi Cup AI WEB)
After=network.target
StartLimitIntervalSec=0

[Service]
Type=simple
User=shiguang
Group=shiguang
WorkingDirectory=/opt/shiguang/current/apps/server
EnvironmentFile=/opt/shiguang/shared/.env
Environment=PYTHONDONTWRITEBYTECODE=1
ExecStart=/opt/shiguang/venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8720 --workers 1
Restart=always
RestartSec=3
UMask=0027
StandardOutput=journal
StandardError=journal
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/opt/shiguang/shared
CapabilityBoundingSet=

[Install]
WantedBy=multi-user.target
```

| 加固项 | 作用 |
|---|---|
| `User/Group=shiguang` | 进程无 root 权限，Web 漏洞拿不到系统写权限 |
| `NoNewPrivileges=yes` | 禁止 setuid/提权 |
| `ProtectSystem=strict` | 整机文件系统只读，只放开 `ReadWritePaths` |
| `ReadWritePaths=/opt/shiguang/shared` | 只允许写 `app.db` 与 `upload/` |
| `ProtectHome=yes` | 看不到 `/root`、`/home` |
| `PrivateTmp=yes` | 私有 `/tmp`，防与宿主临时文件互相影响 |
| `CapabilityBoundingSet=`（空） | 丢弃全部 capability；8720 非常规端口，不需要特权 |
| `UMask=0027` | 新建文件不带组/其他写权限 |

单 worker：SQLite 写并发低，多 worker 反而抢锁；1.6 GB 内存也只够一个。

## 6. 公网防护

| 措施 | 实现位置 | 说明 |
|---|---|---|
| Basic Auth | `app/core/security.py` | `/api/health` 免认证，其余全部需要；部署脚本拒绝空口令启动（见 §3） |
| 限流 | `app/core/security.py` | 每 IP 60 s 滑动窗口 **120 次**；`/`、`/index.html`、`/assets/*`、`/api/health` 与 dist 内真实静态文件（logo/hero/favicon）豁免，其余路径（含 `/api/*` 与 SPA 路由）计数 |
| 上传上限 | `app/core/security.py` + `config.MAX_UPLOAD_BYTES` | 8 MB，按 `Content-Length` 拦截，前端同源常量 |
| 密钥脱敏 | `app/core/safety.py` + `config.describe()` | 日志只留末 4 位 |
| 关闭文档 | `app/main.py` | 启用 Basic Auth 时 `docs_url=None` |
| 静态资源解析 | `app/core/webdist.py` | dist 内真实文件直接回文件（含目录穿越防护），其余回 index.html；`/assets/*` immutable、公共文件 1 h、index.html `no-cache` |

限流为什么是 120 且豁免静态资源：首页一次 20 个请求（HTML/CSS/JS/字体），旧配置 30 次/分钟把静态资源也算进去，刷新两次就 429；静态资源与首页豁免后，120 次/分钟约等于 20–30 次有效操作，录屏与评委试用都够。

**为什么需要 webdist**：Vite 把 `apps/web/public/` 原样拷到 `dist/` 根（logo.svg / hero-kitchen.jpg / favicon.svg），而 FastAPI 只挂了 `/assets`。2026-11-17 之前这些根级文件被 catch-all 回退成 index.html（`200 text/html`），线上表现为侧栏碎图、首页 hero 无图，dev 模式却正常。发布后必须复验 `curl -I .../logo.svg` 的 Content-Type 是 `image/svg+xml`（见 §8）。

## 7. 日常发布

```powershell
pwsh -File scripts/deploy.ps1
```

与首次部署同一条链路，只有第 6 步不同（不跑 `install.sh`，直接切链重启）。要点：

- 所有 `ssh`/`scp` 带 `-o BatchMode=yes -o ConnectTimeout=10 -o StrictHostKeyChecking=accept-new`：密钥不对立即报错，不会挂在交互口令上；
- `pnpm install --frozen-lockfile` 与 `pnpm build` 都检查退出码，失败即停（不会把旧 `dist` 当新构建发出去）；
- 必需文件缺失直接 `throw`；
- 远端解包后统一 `umask 022` + 755/644 + `chown -R root:root`；
- 健康门失败自动切回上一 release，脚本 `exit 1`；
- 成功后保留**最近 3 个 release**（另始终保留 `current` 与上一版），并写 `last-deploy.txt`；
- 本地临时目录与 `.tar.gz` 在 `finally` 中清理。

unit 文件变更时：重跑 `-FirstRun`（`install.sh` 会覆盖 unit 并 `daemon-reload`），或手工 `install -m 644 deploy/shiguang.service /etc/systemd/system/ && systemctl daemon-reload`。

## 8. 验收（部署后逐条打）

```bash
# 1) 健康门（无需认证；-f 保证 4xx/5xx 不返回 0）
curl -fsS http://127.0.0.1:8720/api/health          # {"ok":true,"provider":"mock","db":"ok"}

# 2) 匿名访问必须 401，静态站必须 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8720/
curl -fsS -u demo:<口令> -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8720/

# 3) 连续刷新首页不应出现 429（静态资源已豁免）
for i in $(seq 1 5); do curl -s -o /dev/null -w '%{http_code} ' -u demo:<口令> http://127.0.0.1:8720/; done; echo

# 4) 进程与加固项
systemctl status shiguang --no-pager
systemctl show shiguang -p User -p Group -p NoNewPrivileges -p ProtectSystem -p ReadWritePaths

# 5) 权限（应全部 755/644，shared 见 §2）
stat -c '%a %U:%G %n' /opt/shiguang/current/apps/server/app/main.py /opt/shiguang/current
stat -c '%a %U:%G %n' /opt/shiguang/shared/.env /opt/shiguang/shared/app.db /opt/shiguang/shared/upload

# 6) 发布记录
cat /opt/shiguang/last-deploy.txt

# 7) public 根级资源必须回真文件（不是 text/html）
curl -sI -u demo:<口令> http://127.0.0.1:8720/logo.svg | grep -i content-type      # image/svg+xml
curl -sI -u demo:<口令> http://127.0.0.1:8720/hero-kitchen.webp | grep -i content-type  # image/webp
curl -sI -u demo:<口令> http://127.0.0.1:8720/stats | grep -i cache-control        # no-cache
```

浏览器侧再验一次：`/` 弹 Basic 登录 → 首页 6 个页面可点 → 侧栏 logo 与首页 hero 图正常显示 → 拍照识别/对账/周报走通 → 控制台无 429、无碎图。

## 9. 回滚

自动（发布时）：健康门失败 → 切回**发布前记录的上一 release**（同一值写进 `last-deploy.txt`）→ `systemctl restart` → 若仍不健康则打印日志并 `exit 1`。

手工（一条命令）：

```bash
ln -sfn /opt/shiguang/releases/<上一时间戳> /opt/shiguang/current && systemctl restart shiguang
curl -fsS http://127.0.0.1:8720/api/health
```

`releases/` 只保留最近 3 个（+ current + 上一版），更早的回滚需重新发布。

## 10. 备份

`app.db` 是唯一状态（`upload/` 是原图，属可选）。SQLite 热备份用 `.backup`，不要直接 `cp` 正在写的库（服务器无 `sqlite3` 时先 `apt-get install -y sqlite3`）：

```bash
# 备份（root）
mkdir -p /opt/shiguang/backup
sqlite3 /opt/shiguang/shared/app.db ".backup '/opt/shiguang/backup/app-$(date +%Y%m%d-%H%M).db'"
chown root:root /opt/shiguang/backup/*.db && chmod 640 /opt/shiguang/backup/*.db
# 保留最近 7 份
ls -1t /opt/shiguang/backup/app-*.db | tail -n +8 | xargs -r rm -f

# 恢复（先停服，避免半截写入）
systemctl stop shiguang
cp /opt/shiguang/backup/app-<时间戳>.db /opt/shiguang/shared/app.db
chown shiguang:shiguang /opt/shiguang/shared/app.db && chmod 640 /opt/shiguang/shared/app.db
systemctl start shiguang && curl -fsS http://127.0.0.1:8720/api/health
```

备份文件含演示数据不含 key（key 在 `.env`）；`.env` 改动前后在台账留版本说明，不随库备份外传。

## 11. HTTPS 风险（务必知情）

现状是 **HTTP 明文 + Basic 认证**：口令 base64 只做编码，链路上可被还原。演示期缓解：

- 使用一次性演示口令，活动结束立即轮换或直接下线（见 §13）；
- 不填真实付费模型 key，或只填限额 key（泄露损失可控）；
- 不通过公网访问上传真实家庭照片/小票，演示用样图；
- 演示使用公网地址并保持评审期可用；Tailscale 仅作运维入口。

要做 TLS 时（推荐 Caddy 反代，二选一）：

- 有域名：`caddy reverse-proxy --from <域名> --to 127.0.0.1:8720`（自动签证书，安全组放 80/443）；
- 无域名：Cloudflare Tunnel / `ssh -R` 临时隧道，保持 uvicorn 只监听 `127.0.0.1`。

上 TLS 后把 unit 的 `--host 0.0.0.0` 改 `127.0.0.1`，只让反代对外。

## 12. 存量线上修复（一次性）

已经在线、但仍是 root 跑 + 文件 666/777 的机器，执行 `deploy/harden-existing.sh`：

```bash
scp deploy/shiguang.service deploy/harden-existing.sh root@<host>:/tmp/shiguang-deploy/
ssh root@<host> 'sed -i "s/\r$//" /tmp/shiguang-deploy/harden-existing.sh; bash /tmp/shiguang-deploy/harden-existing.sh --yes'
```

> 本机 `core.autocrlf=true` 时 `.sh` 检出为 CRLF，远端 `bash` 会在首行 `\r` 处报错；先去掉 `\r` 再执行（`deploy.ps1 -FirstRun` 内部已自动转 LF）。

它只做：建 `shiguang` 用户 → 收紧 `releases/*` 与 `shared` 归属/权限 → 装加固 unit → `daemon-reload` → 重启 → `curl -fsS /api/health` 健康门（失败打印日志 `exit 1`）。
**不改 `.env` 内容、不切 release、不动数据库数据**；限流 120 需另行改 `.env` 后重启。脚本不生成空 `.env`，缺失 `.env` 或 `SHIGUANG_BASIC_AUTH` 为空都会直接报错退出（不在无认证状态下重启公网服务）。

## 13. 费用与清理

- 默认 `mock` 不产生 token 费用；切 `zhipu` 后按调用量计费，限流 120 次/分钟（只计 `/api`）足够录屏与评审试用。
- 下线（国赛结束后）：`systemctl disable --now shiguang && rm -rf /opt/shiguang`，并从 `TASKTABLE.md` / `PORTTABLE.md` / 台账移除；cloudserver200m 上的 8720 安全组规则一并收回。
