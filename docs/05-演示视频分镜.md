# 05 演示视频分镜（食光）

> 用途：5–8 min 提交视频的唯一拍摄脚本。口播可直接照念，不要临场改词。
> 目标时长 **6:35**（硬上限 8:00，留 1:25 余量；若某段超时，只补录该段，不整片重来）。

## 0. 拍摄规格（先定死，避免返工）

| 项 | 值 |
|---|---|
| 分辨率 / 帧率 | 1920×1080 / 30 fps，H.264，8–12 Mbps |
| 音频 | 普通话，单声道 48 kHz；峰值 −6 dB，底噪 < −45 dB |
| 浏览器 | Chrome，窗口 1600×1000，缩放 110%，隐藏书签栏与标签页 |
| 字幕 | 全部烧入，思源黑体 Medium 40 px，白字 + 30% 黑描边 |
| BGM | 无，或 −28 dB 极轻钢琴（不盖人声） |
| 鼠标 | 移动放慢到平时的 70%，点击前停顿 0.3 s，不甩鼠标 |
| 禁止出现 | 任何 API key、`.env` 真实值、个人姓名/学号/手机、桌面其他文件名 |
| 语速与留白 | 口播按 **4.5 字/秒** 估算，全片约 1400 字 ≈ 5:12 纯语音；每段另留 10–15 s 给加载态与操作，合计 6:35 |

## S1 · 0:00–0:30 痛点与定位（30 s）

| 项 | 内容 |
|---|---|
| 画面 | 黑场 1 s → 首页静态图（不操作）→ 0:08 鼠标移到「拍冰箱」按钮停住 |
| 口播字数 | 约 135 字 · 4.5 字/秒 |
| 强调 | 「库存时效管理，不是菜谱推荐」——一句话把自己和竞品分开 |

**口播**：

> 先说个常见的场面。周五买的青菜，塞进冰箱第二层，周三想起来，已经烂了。
>
> 这不是你不会过日子，是冰箱不会提醒你。菜谱 App 解决的是「我想吃什么」，没人管「我冰箱里什么快坏了、今天必须吃掉什么」。
>
> 食光就干这一件事：拍一张冰箱照片，三秒知道哪些快坏了、今天做什么，月底看到自己少扔了多少。

## S2 · 0:30–1:30 拍照识别与人工校对（60 s）

| 项 | 内容 |
|---|---|
| 画面 | ①点「拍冰箱」→ 选本地照片 ②上传中骨架屏 1.5 s ③结果卡片逐条出现（带置信度条） ④镜头停在 0.62 那一条的黄标 + 顶部提示条 ⑤把「青椒」改成「尖椒」、数量 1→2 ⑥点「确认入库」→ 看板计数 +6 |
| 口播字数 | 约 250 字 |
| 强调 | ①**不直接入库**，必须人工确认；②置信度可视化；③错得能改 = 承认模型会错 |

**口播**：

> 这是首页，主要就一个动作：拍照。我选一张自己拍的冰箱照片，上传。
>
> 后端把图片转成 base64 交给视觉模型，让它按我们定好的 JSON 结构返回：食材名、数量、单位、还有置信度。三秒左右，结果出来了。
>
> 注意两件事。第一，识别结果不会直接进库存，它先变成一个可以改的表单。第二，每一项后面有置信度条——这一项只有 0.62，所以标黄，顶部也提示我先确认它。
>
> 识别错很正常，关键是错了能改：青椒改成尖椒，数量从一改成二。改完点确认，才真正写进库存，同时按食材表算出到期日。

## S3 · 1:30–2:15 临期看板（45 s）

| 项 | 内容 |
|---|---|
| 画面 | ①看板按剩余天数排序 ②依次高亮绿/黄/红三档，停 1 s ③底部灰色「已过期」区块 ④点一张卡改到期日（+2 天）→ 颜色由红变黄 ⑤刷新页面，数据还在 |
| 口播字数 | 约 185 字 |
| 强调 | 排序轴是「还会活几天」，不是名字；刷新不丢 = 真落库 |

**口播**：

> 这是看板。它不按名字排，按剩余天数排。绿色是四天以上，黄色是两到三天，红色是明天或者今天就到期，已经过期的单独放最下面。
>
> 每张卡片能直接改：数量、到期日、备注。改完立刻重算颜色，刷新页面也不会丢。
>
> 顶上这几个数字是我现在最该关心的：几样要赶紧吃，几样今天必须处理。到这，「冰箱里有什么」这件事，第一次变成了一个看得见的倒计时。

## S4 · 2:15–3:30 AI 菜谱与引用回链（75 s）

| 项 | 内容 |
|---|---|
| 画面 | ①勾选两样红色食材 → 点「今天吃什么」 ②卡片依次出现：时长 / 推荐理由 / 缺料标签 / 匹配分数 ③镜头特写第一张的理由句 ④点引用角标 `[1]` → 右侧抽屉弹出原文，滚动定位到「步骤 1-3」 ⑤关抽屉 ⑥点「开始做」→ 填克数 → 确认 → 返回看板该食材数量减少 |
| 口播字数 | 约 300 字 |
| 强调 | ①不是聊天框，是卡片；②每句结论有角标能点回原文；③检索是两个通道融合；④菜谱是消耗库存的手段 |

**口播**：

> 选两样最急的，点「今天吃什么」。
>
> 它没有丢一个聊天框给我，而是直接给三张卡片。每张上面有四样东西：要做多久、为什么推荐、还缺什么料、还有一个匹配分数。第一张的理由是「用掉你明天到期的西兰花，只要再加蒜和油」——这句话里每个判断都能追到出处，点这个角标，右边弹出原文，直接定位到那本菜谱的第一步到第三步。
>
> 检索这块多说一句。我们用的是 SQLite 自带的全文索引，中文按两个字切开写进去，这样「西兰花」才搜得到；如果开了向量，就把语义召回的结果和关键词结果做一次融合排序，不是二选一。
>
> 最后点「开始做」，填实际用掉多少克，库存就扣掉了。菜谱在这儿不是目的，是消耗库存的手段。

## S5 · 3:30–4:25 Agent 五步 + MCP（55 s）

| 项 | 内容 |
|---|---|
| 画面 | ①打开「运行记录」页，展示刚那次请求的五步：`understand → plan → retrieve → compose → verify` ②每步右侧显示耗时 ms 与一句话摘要 ③展开 `retrieve` 看工具入参 `{ingredients, max_minutes}` 与返回条数 ④切终端，跑一次 MCP stdio 调用 `search_recipes`，回包打印在屏幕上 |
| 口播字数 | 约 230 字 |
| 强调 | ①状态机可回放、有时间戳；②第五步是自检（引用 id 存在、食材在库存、步骤 ≥3）；③MCP 是真进程，不是 PPT |

**口播**：

> 刚才那次推荐，背后是一条五步的流水线：理解意图、规划、检索、生成理由、校验。
>
> 这五步不是写在 PPT 上的。每次请求都会落一条记录，页面上能回放：哪一步用了多少毫秒、调了哪个工具、传了什么参数、拿回几条候选。
>
> 第五步是自检：引用里的菜谱编号必须真实存在，用到的食材必须在你的库存里，步骤不能少于三步。有一条不过就重试一次，还不过就把这条剔掉——宁可少推荐一道，也不推一道编出来的。
>
> 另外还有两个工具，查保质期和搜菜谱，我单独包了一个 MCP Server，终端里能直接调，现在演示一下。

## S6 · 4:25–5:25 浪费率与碳账（60 s）

| 项 | 内容 |
|---|---|
| 画面 | ①统计页：浪费率环图 + 30 天趋势条 ②三个大数字：少扔克数 / 碳当量 / 省下金额 ③等效换算卡片（开车 38 公里 · 一棵树 120 天） ④点「数据口径」弹出说明面板（停 2 s，让评委看清「估算 ±30%」） |
| 口播字数 | 约 260 字 |
| 强调 | ①口径写在页面上，不藏着；②主动承认是估算；③反馈要能"有感" |

**口播**：

> 现在看月底这张账。
>
> 这三十天，我吃掉三点四公斤，扔掉零点七公斤，浪费率百分之十七。旁边这条是每天的趋势，能看出哪几天扔得多。
>
> 碳是这么算的：每样食材在食材表里有一个碳排放因子，单位是「每公斤食材对应多少公斤二氧化碳当量」，扔掉多少克就乘多少。这个月少排五点二公斤。五点二公斤是什么概念？大概等于开车三十八公里，或者一棵树长一百二十天。
>
> 我知道你会问这数准不准。它不准，它是估算，误差我们标在页面上，因子来自公开文献，不是我们拍的。它不用于碳核查，作用是给你一个能感觉到的反馈：扔掉的不是「一点菜」，是钱，也是碳。

## S7 · 5:25–6:00 无 key 降级与密钥安全（35 s）

| 项 | 内容 |
|---|---|

| 口播字数 | 约 140 字 |
| 强调 | ①不静默、不假装成功；②key 只从环境变量读；③错误不甩栈给用户 |

**口播**：

> 最后说兜底。现场网络和环境都不一定靠谱，所以这里有一个开关：把模型提供方切成 mock，不联网也能把整条流程走完，返回的是提前录好的结果，页面顶部会明确告诉你「现在是离线模式」，不假装成功。
>
> 密钥只从环境变量读，不进数据库、不打日志；模型真挂了，返回一句人能看懂的话，不把报错堆栈甩给用户。

## 2. 剪辑与自检

| # | 检查项 | 不合格表现 |
|---|---|---|
| 1 | 总时长 5:00–8:00 | 少于 5 min 或超 8 min 直接不合格 |
| 2 | 1080p 以上 | 用播放器看属性，宽度必须 ≥1920 |
| 3 | 口播与画面对齐 | 说「点角标」时鼠标已经在角标上 |
| 4 | 数字自洽 | `waste_rate = 丢弃 /(丢弃 + 吃掉)`，口播数字须与页面一致 |
| 5 | 无密钥、无个人信息 | 逐帧看 `.env`、终端、桌面 |
| 6 | 字幕无错别字 | 「西兰花」「碳当量」「置信度」这三个词重点核 |
| 7 | 首次出现术语有半句解释 | 置信度、引用角标、mock |

> 口播中的示例数字（3.4 kg / 0.7 kg / 17% / 5.2 kg / 38 km / 120 天）为占位值，录制前必须替换成录屏当时的真实数据，否则评委会拿计算器当场核对。
