# 07 AI 协作方式与原创性说明

> 竞赛要求提交「原创性说明（AI 协作方式与人工判断点）」。本文逐项交代：哪里是 AI 做的、哪里是人做的、怎么证明不是一次性提交。

## 1. 一句话

人定**做什么和不做什么**，AI 按契约**并行写实现**，人**逐条验收**。所有判断权在人手上，所有代码在提交历史里可查。

## 2. 分工表

| 环节 | 主导 | 具体内容 | 可核验证据 |
|---|---|---|---|
| 选题 | **人工** | 3 个候选方案对比（存量资产、评分覆盖、工期风险），最终砍到「冰箱时效管理」 | `docs/01-选题方案对比.md`、`docs/02-RAG选题方案.md` |
| 产品边界 | **人工** | 定 P0 七条 / P1 四条 / 明确「不做」四项（账号、多用户、App、微调） | `docs/03-定稿与契约.md` §2 |
| 技术契约 | 人工起草底线，AI 补细节 | API 字段、表结构、目录所有权、失败降级策略 | `docs/03` §5–§10 |
| 架构拆分 | AI 提方案，**人工定并行边界** | 把工程拆成 A–F 六个互不越界的角色，避免并行改同一文件 | `docs/03` §4 |
| 代码实现 | **AI**（按角色分派） | 后端 API、RAG 索引、Agent 状态机、前端组件与设计系统 | 提交历史 + `apps/` |
| 数据表 | **人工定口径**，AI 填表 | 保质期/碳因子/价格的口径与误差范围由人拍板，AI 只做录入 | `docs/06` §2 |
| 验收 | **人工** | 逐条跑契约 §12 的命令、按 §10 安全项打勾、手工点完整流程 | 验收记录、pytest 输出 |
| 文档 | AI 起草，**人工改写成可念的口语** | 分镜、答辩稿必须人能顺畅念出来，AI 初稿普遍书面语过重 | `docs/05`、`docs/08` |
| 录制 | **人工** | 拍摄、旁白、剪辑，AI 只出脚本 | 视频文件 |

**结论一句话**：AI 是打字的手，不是做决定的大脑。

## 3. 人工判断点（评委最关心的五个）

| # | 判断 | 备选方案 | 为什么这么选 |
|---|---|---|---|
| 1 | 做「库存时效」而不是「菜谱推荐」 | 通用菜谱推荐、聊天式营养师 | 菜谱红海且易被判定为套壳；倒计时才有闭环，且能自然长出浪费率与碳账 |
| 2 | 不训练/不微调模型 | 微调一个食材识别模型 | 3 天工期 + 无标注数据；识别错由**可编辑表单 + 置信度**兜住，比赌模型准更可靠 |
| 3 | 不引 UI 库、不引图表库 | Ant Design + ECharts | 减依赖、减构建体积，评委能看清是手写的；代价是慢，接受 |
| 4 | 识别结果绝不自动入库 | 一键全量入库（体验更顺） | 误识别会污染碳账与浪费率，宁可多一步确认 |
| 5 | 模型挂了降级而不是报错 | 直接 502 | 演示稳定性 > 功能完整度；降级必须**显式提示**，不许假装成功 |

## 4. 细粒度提交：怎么保证不是一次性提交

### 4.1 提交纪律

| 规则 | 做法 |
|---|---|
| 粒度 | 一个「可运行切片」一次提交（如「拍照识别跑通 mock」），不按文件提交 |
| 顺序 | 契约 → 骨架 → 单模块 → 集成 → 文档，每一档都有独立提交 |
| 提交前 | 后端 `pytest -q` 通过、前端 `pnpm build` 通过才允许 commit |
| message | 一句中文，前缀标模块：`feat(capture): 拍照识别接入 mock 与置信度` |
| 禁止 | 不 `--amend` 覆盖历史、不 squash、不 force push、不把三天工作量压成一条 |
| 时间分布 | 提交时间戳自然分散在三个工作日，**不是同一分钟批量刷** |

## 5. 与往届作品的差异点

| 维度 | 常见参赛作品 | 食光 |
|---|---|---|
| 形态 | 聊天框 + 一个 prompt | 拍照 → 表单 → 看板 → 卡片，全程无聊天框主入口 |
| Agent | 说「用了 Agent」，看不到过程 | 五步状态机落库，每步有耗时与摘要，页面可回放 |
| RAG | 向量库 + 相似度截图 | FTS5 关键词 + 向量 RRF 融合，引用角标**点得开、定位到原文** |
| 可信度 | 只展示成功案例 | 置信度条 + 低置信度黄标 + 五步自检剔除机制，把「会错」写在脸上 |
| 稳定性 | 断网就白屏 | `mock` 提供方全链路可跑，降级有显式提示条 |
| 价值闭环 | 停在「给你建议」 | 停在「少扔 0.7 公斤 / 少排 5.2 公斤」的可核对数字 |
| 工程 | 引一堆 UI 库堆页面 | 手写设计系统与 SVG 图表，依赖表短，构建产物小 |

## 7. 可能被追问的三个点（简答）

| 问 | 答 |
|---|---|
| AI 写的代码算你的作品吗？ | 算「人机协作成果」，我们如实标注。判断、约束、验收、取舍由人完成；评委看的是这三点，不是谁敲键盘。 |
| 会不会是 AI 一次性生成的？ | 看提交历史：20 次提交、三天分布、每次提交都是一段能跑的切片，且每次提交前都跑过构建与测试。 |
| 有没有抄现成项目？ | 复用的都是本人往期项目的骨架，且已声明；业务逻辑（倒计时分级、五步自检、碳账口径）为本项目新写。 |
