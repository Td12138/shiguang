# 09 部署方案（cloudserver200m）

## 1. 形态

| 项 | 值 |
|---|---|
| 主机 | `cloudserver200m`：公网 `47.100.224.209`，Tailscale `100.77.67.31` |
| 规格 | Ubuntu / 1.6 GB 内存 / 40 GB 盘 / Python 3.12.3 / systemd 255 |
| 访问方式 | `http://47.100.224.209:8720`（需在阿里云安全组放行 TCP 8720） |
| 进程 | 单进程 uvicorn，systemd 托管，静态资源由 FastAPI 托管（**不装 nginx**，1.6 GB 内存不养多余进程） |
| 模型 | 默认 `mock`（`install.sh` 生成）；要真模型时在服务器 `shared/.env` 填 key 并改为 `zhipu`；key 只存在服务器 |
| 数据 | SQLite 落在 `/opt/shiguang/shared/app.db`，备份即拷文件 |

## 2. 目录布局（发布目录 + 软链，回滚只改一条链接）

```
/opt/shiguang/
  releases/20261117-2100/       # 每次部署一个新目录
    apps/server/...             # 后端代码（不含 .env、不含 app.db）
    apps/web/dist/...           # 本地构建好的静态文件
    mcp/...
  current -> releases/20261117-2100
  shared/
    .env                        # 600 权限，含演示口令与（可选）模型 key
    app.db                      # 运行时数据库
    upload/                     # 用户上传的图片
```

## 3. 构建与上传（Windows 侧）

```powershell
# 1) 前端构建（产物在 apps/web/dist）
cd apps/web; pnpm install; pnpm build

# 2) 打包：只带运行必需文件，排除 .env / app.db / __pycache__ / node_modules
#    由 scripts/deploy.ps1 完成：打包 → scp → 远端解压到 releases/<ts> → 切软链 → 重启

# 3) 首次执行
pwsh -File scripts/deploy.ps1 -FirstRun
```

## 4. 服务端配置（首次一次性）

```bash
apt-get update && apt-get install -y python3-venv   # 其余依赖已在
python3 -m venv /opt/shiguang/venv
/opt/shiguang/venv/bin/pip install -r /opt/shiguang/current/apps/server/requirements.txt
install -m 600 -o root -g root /dev/null /opt/shiguang/shared/.env   # 手工写入口令、（需要时）模型 key
```

`.env`（服务端）关键项（默认 mock，不产生模型费用）：

```
SHIGUANG_LLM_PROVIDER=mock          # 要真模型时改成 zhipu，并填下一行
# SHIGUANG_LLM_API_KEY=<真实 key>
SHIGUANG_DB_PATH=/opt/shiguang/shared/app.db
SHIGUANG_UPLOAD_DIR=/opt/shiguang/shared/upload
SHIGUANG_WEB_DIST=/opt/shiguang/current/apps/web/dist
SHIGUANG_BASIC_AUTH=demo:<口令>
SHIGUANG_RATE_LIMIT_PER_MIN=30
SHIGUANG_SSL_VERIFY=os
```

## 5. systemd 单元 `shiguang.service`

```ini
[Unit]
Description=Shiguang demo (Chuanzhi Cup AI WEB)
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/shiguang/current/apps/server
EnvironmentFile=/opt/shiguang/shared/.env
ExecStart=/opt/shiguang/venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8720 --workers 1
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

单 worker：SQLite 写并发低，多 worker 反而抢锁；1.6 GB 内存也只够一个。

## 6. 公网暴露的防护（演示站必须做，否则会被刷；切真模型时还会刷 key）

| 措施 | 实现位置 | 说明 |
|---|---|---|
| Basic Auth | `app/core/security.py`（`SecurityMiddleware`） | `SHIGUANG_BASIC_AUTH=user:pass`；`/api/health` 免认证，其余全部需要 |
| 限流 | `app/core/security.py` | `SHIGUANG_RATE_LIMIT_PER_MIN`，每 IP 滑动窗口，超限 429；`/api/health` 豁免 |
| 上传上限 | `app/core/security.py` + `app/config.py::MAX_UPLOAD_BYTES` | 8 MB，按 `Content-Length` 拦截，前端同源常量 |
| 密钥脱敏 | `app/core/safety.py` | 日志永不出现 key，只留末 4 位 |
| 关闭文档 | `app/main.py` | 启用 Basic Auth 时 `docs_url=None` |

## 7. 验收（部署后逐条打）

```bash
curl -u demo:<口令> http://47.100.224.209:8720/api/health        # {"ok":true,"provider":"mock"}（配了 zhipu 则为 "zhipu"）
curl -u demo:<口令> -F file=@fridge.jpg http://.../api/capture/recognize
curl -u demo:<口令> http://.../api/inventory
curl -o /dev/null -w '%{http_code}\n' http://47.100.224.209:8720/   # 200，返回首页 HTML
systemctl status shiguang --no-pager
```

## 8. 回滚（一条命令）

```bash
ln -sfn /opt/shiguang/releases/<上一个时间戳> /opt/shiguang/current && systemctl restart shiguang
```

## 9. 上线前后要做的两件事

1. 阿里云控制台安全组放行 **TCP 8720**（只有你能做）
2. 上线后在 `TASKTABLE.md` 登记 `shiguang` 云端 demo（类型：临时服务；清理期限 2026-12-31，国赛结束后下线），`PORTTABLE.md` 的 ECS 段登记 8720

## 10. 费用与清理

- 演示站默认 `mock`，不产生模型 token 费用；切成 `zhipu` 后按调用量计费，限流 30 次/分钟足够录视频与评委试用
- 国赛结束后：`systemctl disable --now shiguang && rm -rf /opt/shiguang`，并从台账移除
